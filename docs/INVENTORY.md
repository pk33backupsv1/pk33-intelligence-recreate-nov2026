## C1 — Scope generation

| | |
|---|---|
| **Code** | `zdash222/bin/zk` (the `scopes` subcommand) |
| **Input** | `zdash222/docs/registers/clones.tsv` + a hardcoded `~/.claude/projects/*/memory` glob + `docs/knowledge/zk-scopes-extra.tsv` |
| **Output** | `zdash222/_logs/zk/scopes.tsv` — `scope<TAB>root` per row |
| **Consumers** | `zfts.py` (via `ZFTS_SCOPES_TSV`), `zk_graph.sh`, `zk_embed.py` |
| **Current state** | 53 scopes (after the 2026-10-31 prune; was 61). Graphify population 46 repo scopes (was 49) |
| **Verdict** | **RECREATE** the policy, keep the mechanism |

**The defect.** The scope list had no policy — it was "whatever `clones.tsv`
said". That admitted:

```
3.24.5            /home/pk33/fvm/versions/3.24.5        ← Flutter SDK, 2.2 GB vendor Dart
zt331-not-worthy  /home/pk33/trash/zt331-not-worthy     ← discarded content
x0-pk-only        /home/pk33/trash/x001-trash-copy/x0-pk-only
claude-memory     × 11 rows, same scope name, different paths
```

`bin/zk` now drops `fvm/` and `trash/` roots at the scope layer (2026-10-31,
`c3fa3e7`), and skips empty `*/memory/` dirs (12 → 7 memory rows).

⚠️ **Why the scope layer and not `clones.tsv`:** `clones.tsv` is regenerated by
`bin/recon_fleet.sh` on every beat, so a hand-edit there is undone within the
hour. The `claude-memory` rows are appended by `bin/zk` itself and are not in
`clones.tsv` at all.

## C2 — The walker (`zfts.py`)

| | |
|---|---|
| **Code** | `efus3/scripts/zfts.py` |
| **Input** | scope roots + `EXTS = {.md, .tsv, .txt}` + the prune/skip lists |
| **Output** | documents + chunks in the FTS/doc store |
| **Consumers** | `zk_embed.py`, `zk vsearch`, `zk_report.sh` |
| **Verdict** | **KEEP** — the exclusion logic is good; it needed one fix (C3) |

**The prune list is well-designed** (verified in the source):

```python
PRUNE_DIRS = {".git", "node_modules", "__pycache__", ".venv", "venv", "dist",
              "build", ".cache", "graphify-out",   # derived code graph, never knowledge
              "tool-results", "shell-snapshots"}
SPINE_RE = re.compile(r"ssot_engine_[^/]*/(dc|rc|sym)(/|$)")  # data spines, not knowledge
HARD_SKIP_EXTS = {".ndjson", ".sqlite", ".sqlite-wal", ".sqlite-shm", ".db"}
```

The comment on `graphify-out` is explicit: *"derived code graph (A-16), never
knowledge"*. And the spine regex encodes the kc-dc-rc doctrine — the data
spines are not knowledge.

`_load_scopes_tsv()` does `scopes.setdefault(scope, []).append(root)` — so
**same-named scope rows merge by appending their roots**, and all memory dirs
are walked. `zk_embed.py` filters on exactly that name
(`scope != 'claude-memory' OR path LIKE '%/memory/%'`), so **renaming the
scope would silently break that filter**. The 11 duplicate rows were
**cosmetic, not destructive** — they are not a data-loss risk.

## C3 — The code graph (graphify)

| | |
|---|---|
| **Code** | `graphify` (pipx at `/opt/pipx/venvs/graphifyy`), driven by `zdash222/bin/zk_graph.sh` |
| **Input** | each repo scope root |
| **Output** | `<root>/graphify-out/graph.json` + `graphify-out/cache/ast/` |
| **Consumers** | `zk_graph.sh --check` (the DoD oracle: "graph.json younger than 48 h") |
| **Current state** | **PAUSED** |
| **Verdict** | **RECREATE** |

**The defects, all measured:**

1. **Runtime.** `zk_graph.sh --missing` took **738 s average over 20 runs**
   against a **10-minute** cron — it overlapped itself perpetually.
2. **It could never succeed.** Every run: `ok=3 red=45`. 45 of 48 scopes RED,
   *every time*. The DoD is a 48-hour freshness check, so a repo that is not
   actively committed to can never satisfy it.
3. **It was thermally destructive.** The CPU package read **89–100 °C**
   (crit 100). The Flutter SDK scope alone produced **230 MB** of
   `graphify-out` (134 MB of it AST cache) and was the scope caught at 100%
   CPU.
4. **The output was never consumed.** `graph.json` feeds nothing but the
   freshness check. `zk_graph.sh`'s own header calls it *"the code-only Lens
   (tree-sitter, no API, 0 tokens)"* — a code graph for the sake of a code
   graph.

**The 2026-10-31 prune** removed the Flutter SDK and `trash/` scopes. The RED
count will fall only once a full pass completes — which is exactly what the
prune made affordable.

**Disk footprint:** 8.0 GB across 43 repos. `efus3/graphify-out` alone holds
**18 dated copies of the same graph** (2026-09-16 → 2026-10-13, 257 MB each).

## C4 — The document store

| | |
|---|---|
| **Code** | the FTS + doc store written by `zfts.py` |
| **File** | `zdash222/_logs/zk/index.sqlite` — **2.27 GB** (+ a stale `index.sqlite.prev`, 898 MB, Sep 15) |
| **Contents** | `docs=35919 chunks=737128` (measured from the last successful `zk embed`) |
| **Consumers** | `zk_embed.py`, `zk vsearch`, `zk_report.sh` |
| **Verdict** | **RECREATE** (regenerable in 125 s) |

**The self-ingestion.** efus3 commit `fd5fa4a83` (2026-09-16):

> zfts: prune graphify-out/ from the walk (**17,701 derived graph files had
> entered the zk index**)

The index was eating its own derived output. The fix is in `PRUNE_DIRS` today,
but it was a **one-off repair of a structural feedback loop** — and it means
the current index's provenance is not guaranteed clean.

**A vector store living under `_logs/`** is a structural smell: nothing in the
path distinguishes "important derived data" from "rotted logs". Whatever the
recreation lands on, give it a home outside `_logs/`.

## C5 — Embeddings

| | |
|---|---|
| **Code** | `zdash222/bin/zk_embed.py` |
| **Input** | the doc store's documents → chunks |
| **Upstream** | `ZK_EMBED_URL`, default `http://127.0.0.1:18095` — **an ssh tunnel to pk31:8095** (the bge-m3 service) |
| **Output** | `vec.sqlite` — 2.3 GB (in `_logs/zk/`), 737,128 chunks |
| **Consumers** | `zk vsearch` (the retrieval path) |
| **Last run** | `ZK EMBED: docs=35919 chunks=737128 new=34 changed=14 removed=0 secs=125.1` |
| **Current state** | **PAUSED — and BLOCKED** |
| **Verdict** | **KEEP the design, RECREATE the placement** |

**The blocker.** `bin/zk_tunnel.sh` maintains `pk33:18095 → pk31:8095`. Its own
header says:

> *Reversal: `pcl_selfcron remove zk-embed-tunnel`; or pk adds `ufw allow 8095`
> on pk31 + `ZK_EMBED_URL=http://pk31.local:8095`.*

**pk31 is unreachable** (tailscale `100.114.44.10:22` timeout). Verified
2026-11-02:

```
$ curl -s -m5 http://127.0.0.1:18095/v1/models   ->  000
$ ss -ltnp | grep 18095                          ->  (no listener)
```

**So `zk-embed` would fail even if re-enabled right now.** The pause is not
what broke it — pk31's unreachability is. Restoring the upstream is Step 4 of
the *recovery* plan (a fleet service, not an intelligence design decision).

**Note the good news in the last run:** `new=34 changed=14 removed=0` — the
index was nearly static. 125 s for 737k chunks. **The embed pass is cheap**;
it was `zk_graph.sh` that was expensive.

## C6 — Context packs (`zprotocols/ctx/`)

| | |
|---|---|
| **Location** | `zexp1/zprotocols/ctx/` — 51 files (25 × `CONTEXT-v1.0.N.md` + sha256), **220 KB** |
| **Producer** | `efus3/scripts/zctx.sh` (`compile`/`verify`), driven by the `zctx-refresh` cron (every 5 min) |
| **Consumers** | `efus3/scripts/{znouns,zdev,zctx}.sh`, `zfts.py`, `claude_home_acceptance.sh`, `write_topology_check.sh` — **six scripts read them** |
| **Verdict** | **RECOVER** — this is content, not derived data, and it has real consumers |

**The latent bug.** The cron is:

```
zctx.sh verify || (zctx.sh compile && git -C .../zprotocols add ctx
                    && git -C .../zprotocols commit -qm '...' && git push -q github main)
```

The `git add` sits inside the `||` **fallback**. On the success path the files
are **staged and left in the index** — 9 files (`CONTEXT-v1.0.16` → `v1.0.23`
+ sha256s + `LATEST.md`) accumulating.

⚠️ **This is not the intelligence layer's business** — it is a context-pack
integrity issue, so it is tracked as Step 7 of the *recovery* plan. **It needs
pk's answer**: is the intent "always commit" or "commit only on failure"?

**Why this matters for the KG:** `zfts.py` reads `zprotocols`. If the ctx
packs are staged-never-committed, the KG is indexing a *stale* copy of them
from the last committed state.
